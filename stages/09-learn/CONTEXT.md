# 09 Learn — required after every use

Read `docs/learning.md` and load applicable adopted lessons before the next assignment. End each completed, blocked, failed or interrupted run with a private retrospective when able; an explicit user stop always takes precedence. Learning is independent of publication/registration, so failures can teach the system without being mislabeled successful deliveries.

Run `retrospect <project> <outcome>`. Inspect actual failures, source conflicts, root rework, visual comparisons and customer-journey outcomes. Fill learning.json with evidence-bound observations, causal hypotheses, an intervention, before/after evidence, independent root review and next-run checks. Automatic metrics are a starting point, not analysis or proof that the site is good.

For a defect: identify the owning stage, predict how a changed rule/test would prevent it, reproduce it, make the smallest correction, then compare against the same case. Run the relevant regression plus the whole kit suite when tooling changes. For a success: retain the pattern with evidence instead of inventing a rule merely to change files. Hold an unproven hypothesis with a concrete next experiment.

Root integrates proven generic lessons into the owning context/rule, a fictional regression fixture and .icm/learning/LESSONS.json after the wave. Use one reviewed architecture-update commit per wave when practical; do not mutate instructions under active workers. Pin the new commit for the next batch. Keep prospect names, contacts, actual assets, notes, private snapshots and account details out of public lessons.

An adopted action needs independent review, privacy review, distinct before/after evidence, regression references and the actual promotion commit. `learning-candidate` writes a sanitized candidate only; it does not make a rule active. Root verifies the real patch/tests and updates the adopted registry. Never weaken facts, permissions, privacy or release gates to make scores look better.

Run `gate <project> learn` before final handoff. It works without a successful deployment. Record the changed architecture version or retained/held result. One retrospective and one bounded improvement cycle per use prevents an infinite self-edit loop; unresolved experiments become next-run work. A learning pass does not authorize outreach or continuing after a stop request.
