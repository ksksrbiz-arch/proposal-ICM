# 04 Build — execute the authored page plan

Read the design, routes, flows and asset packets. Own only the assigned project folder. Preserve existing work and originals; never overwrite another worker's files or stop its server. Use an ephemeral localhost port or assigned port. Build the real route set before polishing the opening.

Implement shared navigation/footer, distinct page layouts, current-page state, direct deep links and meaningful related content. Use semantic HTML, labels, visible focus, reduced-motion support, keyboardable galleries/dialogs and truthful loading/empty/error states. Main phone copy should normally be 16px+; fine print may be smaller if readable. Primary touch actions should be about 44px; test crowded controls, zoomed text and short screens.

Keep original photos intact; use responsive derivatives with a full-image viewer when useful. Prevent layout shift with dimensions/aspect ratios. Avoid tiny display text, cropped faces/garments/artwork, obstructive sticky bars, full-screen empty hero space and decorative controls that do nothing. Imagegen output is proposed art, never evidence.

Preserve existing booking/commerce/account destinations. An embed failing under the production frame policy needs a working external path. Local notes need copy failure feedback, download/reset if offered, safe encoding and no fake sent/success claims. Do not make a public form that silently discards information. A real backend requires explicit scope, verified delivery, privacy and abuse controls.

`implementation.json` records reproducible build command, source path, exact public allowlist and build stamp. The allowlist contains only release files relative to outputDir. Include a public `deployment.json` identity marker and custom 404; config-only files such as `_headers` must be identified separately for remote checks. Use noindex meta and X-Robots-Tag on preview HTML, robots policy and visible independent-proposal labeling. Private artifacts stay outside outputDir.

Exit: build gate checks route coverage, allowlist equality, paths, marker identity and banned file classes. It does not prove visual quality. Do not deploy from this stage.
